## Inherited from M0

### Re-verify decorator contract under real session ✅ resolved

The M0 `@require_role` decorator read `user_id` from `kwargs["user_id"]`. At M1 the
contract is replaced: both `@require_role` and `@audit_action` read from `args[0]`
(the Reflex State instance) via `args[0].current_user_id`. A new `@public_handler`
decorator marks intentionally unauthenticated handlers.

- `durgam/auth/decorators.py` — rewritten with State-aware wrappers
- `tests/unit/test_auth.py` — updated to new contract (mock State as `args[0]`)
- Decision: M0 kwargs pattern is removed by design; not backward-compatible.
- Documented in `docs/modules/auth.md` → Decorator Contract section.

### "Brute-force test blocked"

**How demonstrated (two levels):**
- **E2E (gate):** `TestBruteForce::test_brute_force_triggers_lockout` — submits 5 wrong
  passwords in Playwright, asserts lockout message, asserts correct password also fails
  during lockout. Threshold: `AUTH_USER_FAILURE_THRESHOLD=5`; triggers on 6th attempt.
- **Integration (always-on CI):** `TestLogin::test_lockout_after_threshold` — verifies
  `user.locked_until` is set after the threshold; `TestIpRateLimit::test_ip_rate_limit_triggers_rate_limit_exceeded`
  — verifies `RateLimitExceeded` propagates from `login()` when IP limit (default 20) is
  exceeded. Test uses monkeypatched limit=3; triggers on the 4th call.

**Status:** ⬜ Integration tests ✅ green. E2E pending.
