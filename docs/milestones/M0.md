## Known limitations and M1 follow-ups

1. **Auth decorators are stub-session-tested.** The `@require_role` decorator reads
   `user_id` from a kwarg rather than from an HTTP session cookie. At M1 when the login
   page and session management are added, the decorator contract must be verified with a
   real session cookie, and the tests in `tests/unit/test_auth.py` must remain green.
   Do NOT describe the M0 decorators as production-ready; they are stub-session-tested.

2. **No E2E tests against a running app.** `tests/e2e/test_home_loads.py` is skipped
   unless `BASE_URL` is set. This is acceptable at M0 (no user journeys). M1 must add
   a login journey E2E test and configure CI to run it.

3. **Font families are system placeholders.** `--font-sans: system-ui, sans-serif` and
   `--font-serif: Georgia, serif` are used until the §17.3 institutional-font sign-off.

4. **`RoleEmail` NULL-scope deduplication.** The unique constraint
   `uq_role_emails_role_scope(role_code, scope_type, scope_id)` does not prevent
   duplicates when `scope_type` and `scope_id` are both NULL (PostgreSQL NULL ≠ NULL).
   The seed uses a SELECT-before-INSERT guard. A proper fix (partial index or COALESCE)
   should be added as part of the first milestone that uses `RoleEmail` in production logic.
