## Configuration governance

| Surface | Configured by | Rationale |
|---------|---------------|-----------|
| Faculty profile (self-edit fields) | Faculty themselves (owner) | RFP §9.7 explicit — "each faculty manages his page/pages/module" |
| Faculty profile (admin-locked fields) | REGISTRAR + REGISTRAR_OFFICE + HR_HEAD | Personnel-record integrity (employee_id, designation, joining_date, dept/campus, employee_type) |
| Faculty bulk import | REGISTRAR + REGISTRAR_OFFICE + HR_HEAD | Operational scale; mirrors M5b user import permission |
| Designation taxonomy additions | SYSTEM_ADMIN | Vocabulary-level decision; affects rule engines |
| ApprovalProcess channel structures (10 FacultyRequest types + existing 4) | SYSTEM_ADMIN | Existing M7 ownership; extended for OR-set stages |
| Sensitive read (Aadhaar, PAN, uploaded documents) | REGISTRAR + REGISTRAR_OFFICE + IQAC_COORDINATOR + IQAC_OFFICE | RFP §9.7 explicit — "Registrar and his office and IQAC coordinator and his office can view all the above information" |
| Faculty deactivation | REGISTRAR + HR_HEAD | Lifecycle event; soft-delete via TimestampedSoftDelete |

**Principle:** Faculty owns their record; Registrar-tier owns personnel-integrity fields; HR_HEAD shares write on admin-locked fields. Sensitive PII view restricted to Registrar + IQAC tiers per RFP. SYSTEM_ADMIN retains god-role override.

### 10 ApprovalProcess seeds — default channel structures

### `channel_definition_json` shape

```json
{
  "version": 1,
  "stages": [
    {"resolver": "dept_head_at_requestor_campus"},
    {"role_codes": ["DIRECTOR", "DEAN"], "chooser": "approver"},
    {"role_codes": ["VC"]}
  ]
}
```

Field semantics:
- `resolver` — named first-stage resolver; takes precedence over `role_codes`. Resolves to a tuple (resolved_role_code, resolved_user_id) OR raises `RequiresRequestorChoice` with candidate list.
- `role_codes` — single-element list means single-role stage; multi-element list means OR-set.
- `chooser` — `"approver"` (previous approver picks at decide-and-forward) or `"requestor"` (requestor picks at submit). Required when `len(role_codes) > 1`. Absent for single-role stages.

### Conditional resolver `dept_head_at_requestor_campus`

```
1. Resolve requestor's Faculty record. If absent, raise NotFacultyError.
2. Find HoD: UserRole where role_code='HOD' AND scope_id=Faculty.department_id (one row max per dept).
3. If HoD exists and HoD's Faculty.campus_id == requestor's Faculty.campus_id:
   → return ("HOD", hod_user_id)
4. Else, find AhoD at faculty's campus: UserRole where role_code='AHOD' AND scope_id=Faculty.department_id,
   join through user_id to Faculty where campus_id = requestor's Faculty.campus_id.
   If found → return ("AHOD", ahod_user_id)
5. Else: raise RequiresRequestorChoice(candidates=[
     ("HOD", hod_user_id_if_any),
     ("DIRECTOR", director_at_faculty_campus_user_id)
   ])
```

Submit flow catches `RequiresRequestorChoice` and presents the picker. Selected (role, user) is recorded as stage 1's resolved value in `ApprovalRequest.resolved_channel_json`.
