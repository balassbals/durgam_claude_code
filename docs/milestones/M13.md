# M13 — Program & Course Management

**RFP reference**: §12, M13 row.

**Goal**: Rich management UI for programs (PEO/PO/PSO editing, regulation forms,
scheme builder, specialisation editor, exit-level editor) and courses (extended
fields: course_type, delivery_mode, mooc_agency, IKS flags). These entities and
their seed data exist from M3; M13 completes the full CRUD UI.

---

## Inherited from M3

### Course type-based department dropdown filtering

From M3 manual verification: when `course_type` is added to `Course` in M13, the
course create/edit form's department dropdown must be conditional on `course_type`:

- **DSC, DSE, MDC** (core curriculum): dropdown filtered to departments running
  the program via the `ProgramDepartment` join. If only one department runs the
  program, the dropdown is locked to that department (no selection needed).
- **AEC, SEC, VAC, Internship, Research Project, Minor** (general): dropdown
  shows all active departments.

The `ProgramDepartment` model exists at M3. The conditional dropdown logic and
`course_type` field are M13 work.

Source: informal requirements doc (DURGAM.docx) Course Module section.
Tracked in `docs/coverage_matrix.md` row "Course (extended)".

### Credit-hour ratio configurability

From M3: `PRACTICAL_CREDIT_RATIO` is a global constant (`= 2`) in
`durgam/states/config_course.py`. Credits are auto-derived from lecture, tutorial,
and practical hours using:

```
credits = lecture + tutorial + (practical // PRACTICAL_CREDIT_RATIO)
```

At M13, this ratio becomes a field on `ProgramRegulation` with default value `2`,
allowing different programs to have different practical-to-credit ratios. The course
create/edit form should read the ratio from the course's program's active regulation.

The service-layer credit computation (`CourseService.create` / `.update`) should
also accept the ratio as a parameter at M13 rather than reading a module-level
constant.
