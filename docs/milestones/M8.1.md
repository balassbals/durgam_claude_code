## Lessons learned

### Reflex API drift (Phase 4 hotfixes)

Three Reflex idioms that produced silent or runtime failures in M8.1:

1. **`nav_shell()` takes no positional arguments.** Passing the page content as a child (`nav_shell(content)`) is wrong; wrap both `nav_shell()` and the content in the same `rx.vstack`. Fixed in `1a6c00f`.
2. **`rx.select.root` uses `on_change`, NOT `on_value_change`.** `on_value_change` is a different prop that fires on internal Radix events; it does not pass the selected value to the state handler. Fixed in `6589fce`.
3. **`rx.input(type="hidden")` renders visibly** in Reflex 0.9.x. Carry IDs via explicit state vars (`self.edit_request_id`), not hidden form inputs. Fixed in `baa8ffe`.

Rule: check the Reflex 0.9.x changelog before using any new prop. When a callback or hidden field "doesn't fire," check the prop name first.

### Seed-after-permission-change

Every phase that adds new permission triples to `scripts/seed.py` must run `uv run python scripts/seed.py` against the dev DB before the manual walkthrough. Missing this step produces `PermissionDenied` for every user even when the code and seed are syntactically correct. Surfaced at Phase 8 when `leave_request_admin:write:*` was added but not re-seeded.

### Manual walkthrough is the primary quality gate

Across M8.1 the manual walkthrough caught:

- Phase 4 Reflex API bugs (three hotfixes — invisible to pytest)
- Phase 4.1 fixture defect (CSV fixture referenced seeded username that didn't exist in test DB)
- Phase 7 sticky-column non-functionality (two failed approaches; both produced green tests)
- Phase 8 `admin_change_state` Bug A (`cancel()` guard too narrow — PermissionDenied for leave_request_admin role)
- Phase 8 `admin_change_state` Bug B (approved→cancelled produced state="withdrawn")
- Phase 8.3 elapsed-window UX defect (UI permitted impossible transitions)

Green test suites verified correctness of individual service/repo/state methods. The walkthroughs verified that the integrated flow worked end-to-end. Both are required.

### CC reporting reliability

Across Phases 4.1–8, CC delivered under-spec reports (missing verbatim outputs) and in Phase 8 outright fabricated the suite total (claimed "1223 passed"; reality was approximately 1167 passed + 56 failed due to TD-034 fixture contamination). Do not treat suite totals in CC reports as ground truth. Bala runs `uv run pytest tests/unit/ -q --no-cov` and the scoped integration command himself for the gate-passing evidence. Treat CC's reports as a diff summary and the test counts as approximate.

### TD-034 scoped-run discipline

Full-suite `pytest` (bare, or `tests/unit/ tests/integration/`) produces 56 consistent false failures in `tests/integration/test_m5b_purchase_rules.py` due to `seeded_session` / `db_session` fixture-pool interaction. This is pre-existing (filed at M8). Workaround for M8.1 gate: scope runs to `tests/unit/` and the seven leave-specific integration files separately. Never count or compare a bare full-suite run — the false 56 inflate the failure count and mask real regressions.

### Phase 9 E2E selector defects (Radix Select + date inputs)

Two E2E tests required selector fixes after the main M8.1 work merged:

1. **`test_per_employee_form_save`** — `[data-value='faculty_user']` never attached.
   Root cause: Radix Select items render as `<div role="option">` in a browser portal,
   NOT with a `data-value` attribute. Must open trigger → wait for
   `get_by_role("option").first` to attach → click by `get_by_role("option", name=...)`.
   Second dropdown (leave type) requires `.nth(1)` on the combobox locator — not
   `.first`, which re-opens the employee dropdown. Use full display label with
   `exact=True` for abbreviation-collision avoidance ("EL – Earned Leave", not "EL").

2. **`test_apply_past_date_shows_postfacto_badge`** — SKIPPING because `get_by_placeholder("YYYY-MM-DD")` returned empty.
   Root cause: `rx.input(type="date")` renders no `placeholder` attribute. Must use
   `page.locator("input[type='date']")`. Also added a `page.wait_for_timeout(800)`
   stabilization pause after heading visibility — button rendered by same WebSocket
   state delta but not yet settled in Playwright's DOM registry.

Both patterns are now in CLAUDE.md under "Patterns established at M8.1". Fixed in commit `132966f`.

### Phase 9.2 UX polish: column headers and checkbox descriptions

Two UX issues discovered on `/admin/leave/credit-policy` after M8.1 shipped:
1. The data table had no column header row — column identity was inferrable only from
   the edit form labels.
2. The "Enabled" checkbox had no inline label or helper text.

Fix: explicit `rx.hstack` column header row above the `rx.foreach` loop; checkbox
wrapped in `rx.vstack(rx.hstack(checkbox + label), helper_text)`. Page-only change;
no model/service/migration changes. Fixed in commit `a30f4e4`.

**Pattern**: Any `rx.foreach`-based data list that doesn't use `data_table()` must add
an explicit header row. Every checkbox must have an inline label AND a one-line helper
text. See CLAUDE.md under "Patterns established at M8.1".
