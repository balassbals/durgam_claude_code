# M10.5 — UI / Design System

**Goal:** Close the visual-layer gap found at the M10 close audit — an under-specified theme (`durgam/theme.py`, 17 tokens defined against 29 referenced), no type/spacing/radius/elevation/motion scales, and placeholder (`system-ui`/`Georgia`) fonts — by establishing a full design-token system and then migrating the existing pages onto it.

**Scope:** wide desktop only. Mobile responsiveness is explicitly out of scope for this milestone; dead mobile scaffolding is removed in Phase 7, not carried forward as a live target.

**Branch:** `m10-5-ui`.
**Predecessor:** `main` at `2eb8b0b` (tag `m10-close`).

**Audit findings that motivate this milestone** (measured at M10 close):
- `var(--color-background, #f5f0eb)` appears 62 times and always falls back — the page background renders `#f5f0eb`, not the intended ivory `#FAF7F2`.
- `var(--color-danger, #c0392b)` appears 34 times and always falls back — two competing reds shipped (`#A93226` defined vs `#c0392b` fallback).
- `#27ae60` green and `#b45309` amber render despite belonging to no palette.
- `var(--color-rule, #d8d8de)` — the token is warm gold `#B89B6A`; the fallback is a cool grey.
- 16 distinct font sizes with no scale; the three most frequent (`0.85rem`, `0.875rem`, `0.8rem`) are visually indistinguishable and used 565 times combined.
- 9 border-radius values including `var(--radius-2)`, which was undefined.
- Across ~59,000 lines: only 14 `box_shadow`, 10 `transition`, 11 `_hover` usages — almost no elevation or motion language.
- Both font families were `system-ui`/`Georgia` placeholders — no typographic identity.

## Q-decisions

**Q-M10.5.1 — Retain the RFP Puttaparthi palette.**
The M10 close audit's problem was under-application (undefined tokens silently resolving to accidental fallback colours), not the palette itself. Indigo `#1F3A6E`, saffron `#C75B12`, ivory `#FAF7F2`, gold `#B89B6A`, and slate `#2C2C2C` are institutionally grounded (§15.1) and are retained verbatim. The design system is built *around* them, not as a replacement.

**Q-M10.5.2 — Typeface selection: Fraunces (display/serif) + Inter (sans).**
Both are variable fonts under the SIL Open Font License — no licensing constraint for an institutional deployment. Fraunces is warm and distinctive, pairing naturally with the ivory/gold palette for headings; Inter is optimized for the small UI sizes (13–14px) this dense administrative UI relies on. `--font-mono` uses a system monospace stack (no additional font download) for the occasional code/ID display need. Fonts are self-hosted under `assets/fonts/` (latin + latin-ext subsets, ~264KB total) rather than loaded from Google Fonts at runtime, for reliability and privacy — this is a university system, not a public marketing site.

**Q-M10.5.3 — Mobile responsiveness dropped for this milestone.**
The RFP's two-tier responsive table pattern (established at M2) remains supported at the component level, but no new mobile-specific work is undertaken in M10.5. Existing mobile scaffolding that Phase 7 finds to be dead code is removed rather than maintained.

**Q-M10.5.4 — Sidebar chosen over grouped top-bar dropdowns; `nav_shell()` couldn't be rewritten in place, so Phase 2 split into 2a/2b.**
Phase 2's diagnosis found `nav_shell()` invoked as a zero-argument sibling inside each page's own `rx.vstack(...)` at all 67 call sites — it has no access to page content and cannot lay out sidebar\|content. Three options were considered: (B) keep the horizontal bar and render groups as dropdowns — rejected, since 7 dropdowns doesn't solve the problem when one dropdown holds 31 items, and it abandons the locked sidebar decision; (C) build the sidebar machinery this phase but leave `nav_shell()` rendering the old flat bar until Phase 3 does the real per-page swap — rejected, since it ships invisible machinery and still needs the same 67-file edit later; (A) accept editing page files now, proven first on a representative subset. Took (A), split as 2a (prove the mechanism on 5 pages covering every structural variant) / 2b (mechanical rollout to the remaining ~62) — the same checkpoint discipline used at Phase 10A→10B. The old standalone Phase 3 (page shell + container system) dissolves into 2a/2b: `app_shell()` is where `max_width` now lives, and those 67 files were already Phase 3's edit surface — consolidation, not scope creep.

Auth-gate parity: `admin_page()` gates on `BaseState.admin_authorized`; some pages (e.g. `leave/my_leave.py`) instead gate directly on `rx.cond(AuthState.current_user_id != "", ...)`. `app_shell()` does **not** absorb either gate — it stays a pure layout component, composed with whichever gate the page already had (`admin_page(app_shell(...))` or `rx.cond(..., app_shell(...), rx.fragment())`), so each page's auth behaviour is unchanged byte-for-byte.

## Phase 1 — detail

**Shipped:** `durgam/theme.py` expanded 17 → 76 tokens. All 12 previously-referenced-but-undefined tokens now resolve to palette-consistent values (never to the accidental fallback values `#f5f0eb`, `#c0392b`, `#27ae60`, `#b45309`, `#d8d8de`):

| Token | Resolved value | Rationale |
|---|---|---|
| `--color-background` | `#FAF7F2` | Same ivory as `--color-surface` — the two-tone system's page-background half. |
| `--color-card-bg` | `#FFFFFF` | White cards on the ivory background — the two-tone system's card half. |
| `--color-surface-2` | `#F6F1E9` | Secondary/nested panel surface, one step off background. |
| `--color-surface-hover` | `#F1EAE0` | Hover tint for ivory rows/cards. |
| `--gray-2` | `#F1EAE0` | Alternate-row background; kept in the warm family instead of a true (stray) grey. |
| `--color-text` / `--color-text-primary` | `var(--color-body)` | Alias onto the existing slate body colour — one source of truth. |
| `--color-danger` | `var(--color-destructive)` | Collapses the two competing reds into one. |
| `--color-success` | `var(--color-success-border)` | Reuses the M2-established success shade (`#228B22`) instead of the accidental `#27ae60`. |
| `--color-warning` / `--color-warning-text` | `#B7650A` / `#7A4508` | Warm amber-brown, distinct from the saffron accent, not the accidental `#b45309`. |
| `--radius-2` | `var(--radius-md)` | Legacy alias for the 9 existing call sites; flagged for direct-token migration in Phase 5. |

Type scale (7 steps, base body `0.875rem`/14px, paired `--leading-*` line-height tokens):

| Token | Size | Line-height | Weight-neutral use |
|---|---|---|---|
| `--text-xs` | 0.75rem | `--leading-xs` (1rem) | captions, timestamps, badges |
| `--text-sm` | 0.8125rem | `--leading-sm` (1.125rem) | secondary text, table cells, helper text |
| `--text-base` | 0.875rem | `--leading-base` (1.25rem) | body text, inputs, buttons (default) |
| `--text-lg` | 1rem | `--leading-lg` (1.5rem) | card titles, emphasized labels |
| `--text-xl` | 1.125rem | `--leading-xl` (1.625rem) | section headings |
| `--text-2xl` | 1.5rem | `--leading-2xl` (2rem) | page headings |
| `--text-3xl` | 2rem | `--leading-3xl` (2.5rem) | hero / display headings |

Plus weight tokens (`--font-weight-regular/medium/semibold/bold`), a 10-step spacing scale on a 4px base (`--space-1` … `--space-16`), 4 radius tokens, 4 warm-tinted elevation tokens (`--shadow-sm` … `--shadow-xl`, brown-black rgba base), 3 motion durations + 2 easing curves, and 4 container widths (`--container-sm` 640px … `--container-xl` 1760px).

Typefaces self-hosted under `assets/fonts/` (Inter + Fraunces variable fonts, latin + latin-ext subsets from Google Fonts' gstatic CDN, SIL OFL), loaded via `rx.App(stylesheets=["fonts/fonts.css"])` — confirmed working via Reflex 0.9.2's `compiler.compile_root_stylesheet`, which resolves non-URL `stylesheets` entries relative to the `assets/` directory and copies them into the compiled build.

Proof page at `/dev/design-system` (sys-admin only, gated via `_config_guard("system", "configure")`) — a Phase-1 verification artefact, to be removed at Phase 7 / milestone close.

No page migration in Phase 1. Existing pages render unchanged (verified: no `durgam/pages/` file other than the new proof page touched, `durgam/pages/components.py` untouched, no states/services/repositories/models/migrations/seeds touched).

## Phase 2a — detail

**Shipped:** `app_shell(content, container="lg")` in `durgam/pages/components.py` — grouped collapsible sidebar + slim top bar + centred content region + footer, self-contained (never rendered outside a page that explicitly calls it, so it cannot leak onto the ~62 pages still on the old `nav_shell()`).

**Registry (`durgam/nav/registry.py`):** added `NavEntry.order: int = 100` and `GROUP_ORDER = (Personal, Faculty, Approvals, Announcements, Admin, Config, About)`. `get_visible_entries()` now sorts by `(group rank in GROUP_ORDER, group name, order, label)` — unlisted groups sort after all listed ones, alphabetically among themselves. All 31 Config entries got an explicit `order=` (10, 20, 30, …) preserving their existing declaration sequence (already organisational-structure-before-calendar-before-assets); the other 27 entries (Admin, Faculty, Approvals, About, Personal, Announcements) keep the `order=100` default and sort alphabetically within their group — no natural sequence was evident for them.

**State (`durgam/states/base.py`):** `expanded_groups: list[str]` (session-scoped, not browser storage — held on `BaseState`, the same class that renders the sidebar, per the Reflex 0.9 cross-state substate-delta constraint), `toggle_group(self, group_name: str)` (single-arg lookup pattern), `nav_groups` and `group_entry_counts` computed vars, and `_auto_expand_active_group()` (additive — expands the group containing the current route on load, never collapses a group the user closed manually).

**Sidebar rendering:** `_sidebar_link()` is a **new** function, not a rewrite of the existing `_nav_link()` — `nav_shell()` and `_mobile_drawer()` keep calling the original `_nav_link()` completely unchanged, eliminating any risk to the old horizontal bar while both paths coexist. Single-entry groups (Personal, Announcements) render as a plain link with no collapsible header/chevron, decided reactively via `group_entry_counts` (not a static registry-time count), so the same rule holds correctly even for a user whose permissions reduce a normally-multi-entry group to one visible item.

**Layout mechanism:** the sidebar is **not** `position: fixed`. It's a flex child (`rx.hstack(sidebar, rx.vstack(topbar, content, footer))`) with `height="100vh"` on both the sidebar and the content column, each with independent `overflow_y="auto"`. This achieves the same "own scroll when content overflows" requirement as a fixed sidebar without any of the cross-page overlap risk a `position: fixed` approach would have carried (see Q-M10.5.4) — and since it's plain nested flex layout, it is trivially scoped to only the pages that call `app_shell()`.

**Container mapping** (21 ad-hoc `max_width` values → 4 tokens, by content density rather than nearest-pixel-distance): `admin/config/index.py` (tile grid, was 1200px) → `lg`; `faculty/directory.py` (card grid, was 1200px) → `lg`; `approvals/inbox.py` (5-column table, was 1100px) → `lg`; `leave/my_leave.py` (was 1100px) → `lg`; `audit/index.py` (7-column dense table, was 1200px) → `xl`, matching the CLAUDE.md Tier-2 "audit log" dense-table classification.

**Auth-gate parity confirmed for all 5 targets:** `admin_config_index`, `faculty_directory_page`, `inbox_page` all keep `admin_page(app_shell(...))` unchanged from their prior `admin_page(rx.vstack(nav_shell(), ...))`. `audit_log` keeps `admin_page(app_shell(...))`, with `_detail_drawer()` (a `rx.drawer.root` Radix portal, unaffected by DOM nesting depth) folded into the `content` argument as a fragment sibling. `my_leave_page` keeps its own `rx.cond(AuthState.current_user_id != "", app_shell(...), rx.fragment())` — it never used `admin_page()` and still doesn't.

**Tests:** 9 new tests in `tests/unit/test_nav_registry.py::TestGroupOrderingPhase2a` — order defaults to 100, `GROUP_ORDER` matches spec, within-group ordering (explicit order, then label tiebreak), cross-group `GROUP_ORDER` sequencing, unlisted-groups-sort-last-alphabetically (both cases), `order` present in the returned dict, single-entry-group correctness, and permission filtering unaffected by the new sort. 32/32 pass.

**mypy note:** checking `durgam/pages/components.py` and `durgam/states/base.py` individually surfaces mypy errors on the new sidebar code (`BaseState.router.page.path` accessed at class level, `.contains()` on a list Var, `on_click=BaseState.toggle_group(group_name)`). Verified this is not a regression: checking an untouched file (`durgam/pages/admin/config/leave_matrix.py`) with the identical per-file `uv run mypy <file>` invocation surfaces the same error classes (missing-`self`, `func-returns-value`, `Var[Any]` attribute gaps) — this is a pervasive, pre-existing gap between Reflex's runtime Var-wrapping and what plain per-file mypy can model, not something introduced this phase. `ruff check` (the lint actually run per CLAUDE.md's session checklist) shows zero new errors: 8 baseline vs 8 now across all touched files.
