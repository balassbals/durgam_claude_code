## Inherited from M1

### State-layer unit test coverage (Option C carried forward)

At M1, the Reflex State async event handlers (`AuthState.login`, `AuthState.logout`,
`AuthState.change_password`, etc.) have 0% coverage in the normal `pytest` run because
they cannot be exercised without a running Reflex application. Coverage is provided by
the E2E suite (`DURGAM_E2E=1`) but not in the always-on CI unit/integration run.

**M2 decision point:**
> Consider whether Reflex State async handlers should have unit-test coverage via mock
> State fixtures, rather than relying on the E2E suite for state-layer coverage. M1
> deferred this; M2 inherits the question. If M2's state handlers are non-trivial
> (business logic, branching, error paths beyond calling into services), do the work:
> write unit tests that construct a mock State object (see `tests/unit/test_auth.py`
> for the existing `_make_state()` pattern) and call the async handlers directly with
> `asyncio.run()` or `pytest.mark.asyncio`. If M2's handlers are equally thin
> (delegate immediately to a service), document the deferral explicitly here and push
> it to M3.

**What "thin" means:** A handler that does exactly `with open_session() as s: svc.do_thing(s)
and sets one state var is thin. A handler that branches on multiple conditions, sets several
state vars, or has its own error paths beyond re-raising service exceptions is non-trivial.

The existing pattern for mock State objects is in `tests/unit/test_auth.py:_make_state()`.
